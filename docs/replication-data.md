# German Credit, Taiwan Credit и Reweighing

## Запуск и навигация

Из корня репозитория выполните команды ниже. Нужен Python 3.13, зависимости установит `uv`.

```sh
uv sync --locked
uv run --locked python -m fair_credit_scoring.prepare_credit_data
uv run --locked python -m fair_credit_scoring configs/german-reweighing.toml
uv run --locked python -m fair_credit_scoring configs/taiwan-reweighing.toml
uv run --locked pytest
```

- [Подготовка данных](../src/fair_credit_scoring/prepare_credit_data.py) скачивает два CSV из закреплённой ревизии авторов. Для запуска с локальной копией передайте `--raw-dir /путь/к/data/raw` с авторскими `german.csv` и `taiwan.csv`. Скрипт пишет `data/prepared/{german,taiwan}.csv` и `data/prepared/audit.json`. В аудите есть SHA-256, исходные колонки, пропуски и статистика фильтрации. Данные и результаты генерируются локально.
- [Reweighing](../src/fair_credit_scoring/reweighing.py) считает веса по `y` и `a`. [Runner](../src/fair_credit_scoring/runner.py) вызывает его для каждого train и ещё раз при итоговом обучении на всём development. [Тесты](../tests/test_credit_data_and_reweighing.py) проверяют границу возраста, фильтр Taiwan, формулу и сохранение состава validation/test.
- [German TOML](../configs/german-reweighing.toml) и [Taiwan TOML](../configs/taiwan-reweighing.toml) описывают числовые и категориальные признаки и запускают LR/RF с Reweighing. В `outputs/<run_id>/` сохраняются разбиения, предсказания и параметры. Для повторного запуска передайте новый `--run-id` или `--output-dir`.

## Контракт для экспериментов команды

- `row_id` — строковый ID из исходника. Для German это индекс авторского CSV, для Taiwan — UCI `ID`. Сохраняйте его при объединении файлов с предсказаниями. `CREDIT_AMNT` в подготовленном CSV хранится в исходных единицах, его можно присоединить по `row_id` для расчёта прибыли.
- `y=1` означает возврат кредита, `y=0` — дефолт. `score` в файлах предсказаний означает `P(y=1)`, `decision=1` — одобрение.
- `a=0` означает возраст ≤25, `a=1` — возраст >25. Бинарный `AGE` совпадает с `a` и включён в признаки LR/RF по авторской формуле `TARGET ~ .`. Исходный возраст, ID и target в модель не передаются. В тексте статьи обозначения групп обратные, а принадлежность возраста ровно 25 лет следует из кода.
- Для сравнения методов используйте одинаковые данные, `dataset.name`, seed и наборы признаков. Для baseline на том же конфиге вызовите `dataclasses.replace(config, run_id="german-baseline", method="baseline", weight=None, weight_mode="sample_weight")` и передайте его в `run`. Для Taiwan задайте свой `run_id`. Сверьте `split_id` в `run.json`.
- Пока конфиги выбирают модель и порог по balanced accuracy на out-of-fold предсказаниях. Для итогового экономического эксперимента передайте командный profit через `Hooks(metrics={...})` и укажите его в `selection_metric`. Правила общего сравнения описаны в [протоколе](protocol.md).

## Аудит выборок

| Данные | Этап | Строки | Дефолты | ≤25, дефолт / возврат | >25, дефолт / возврат | Ровно 25 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| German | До и после | 1 000 | 30,00% | 80 / 110 | 220 / 590 | 41 |
| Taiwan | До | 30 000 | 22,12% | 1 032 / 2 839 | 5 604 / 20 525 | 1 186 |
| Taiwan | После | 23 531 | 22,92% | 925 / 2 422 | 4 468 / 15 716 | 995 |

В зафиксированных исходниках пропусков нет. Для German объём кредита берётся из `amount` и сохраняются все строки. Для Taiwan `CREDIT_AMNT = BILL_AMT1 − PAY_AMT1`. После условия `CREDIT_AMNT > 0` исключаются 6 469 строк. Это полностью объясняет расхождение с 30 000 строками UCI. Результат для Taiwan относится к клиентам с положительным остатком. Для German в младшей группе всего 190 наблюдений, поэтому оценки по ней чувствительны к составу разбиения.

При подсчёте категорий на полных выборках получается 61 признак для German и 76 для Taiwan, как в таблице 2 статьи. В самом эксперименте словарь категорий строится отдельно на каждом train, поэтому число колонок в конкретном fold может быть меньше.

В Taiwan значения `−2` и `−1` в `PAY_*` объединяются с `0`. Коды образования вне 1–3 и семейного положения вне 1–2 сводятся к `others`, неизвестный код пола — к категории `NA`. В `PAY_*` входит `PAY_0`. Он указан в списке категориальных признаков и сохраняется через объединение списков в авторском `StandardDataset`. Если в локальном файле отсутствует возраст или исход, подготовка останавливается с ошибкой. Строки Taiwan с отсутствующим или неконечным остатком исключаются и учитываются отдельно.

## Метод и отличия от авторского прогона

Вес строки равен `n(a) × n(y) / (n × n(a,y))`. Весовая таблица приводится к независимости группы и исхода, при этом маргинальные числа объектов по группам и исходам сохраняются. Для отсутствующей ячейки `(a,y)` метод выдаёт ошибку с её координатами. На train из 10 объектов с ячейками `[1, 3, 4, 2]` веса равны `[2, 2/3, 3/4, 3/2]`, после взвешивания ячейки дают `[2, 2, 3, 3]`.

| Шаг | Реализация в репликации |
| --- | --- |
| Признаки | Категории и MaxAbs-масштабирование числовых колонок обучаются на исходном train. Для пропусков применяются обученные на train медиана или мода. Неизвестная категория кодируется нулями. Авторы строят one-hot по всему датасету перед разбиением, а MaxAbs обучают на train. |
| Разбиение | 60/40 и пять folds следуют статье. Опубликованный ноутбук задаёт 70/30. Пайплайн команды дополнительно стратифицирует по `(a,y)`, фиксирует ID и дальше переобучает модель на всём development. |
| Ресэмплинг | `weight_mode = "resample"` выбирает столько же строк train, с возвращением, пропорционально весам. Seed зависит от seed прогона и номера fold. Один draw на fold используется для всех моделей и кандидатов. Авторский ноутбук ресэмплит также validation и test с использованием их меток. Здесь обе оценки идут по исходным общим строкам, поэтому состав выборки и веса наблюдений в оценке совпадают с baseline. |
| Подбор модели | Используются LR и RF из scikit-learn, небольшие сетки и пороги из TOML. Авторы используют другой набор моделей и настройку по EMP. Проверочные прогоны здесь используют balanced accuracy. Сравнение чисел со статьёй требует учёта этих отличий. |

## Проверка интеграции

LR и RF отработали с baseline и Reweighing на обоих датасетах с seed 1. Разбиения совпали байт-в-байт. Для каждой модели совпали метки, группы, ID и порядок строк. German дал 600 validation и 400 test предсказаний, Taiwan — 14 118 и 9 413 соответственно. Проверка подтверждает работу пайплайна с общими выборками. Итоговые метрики прибыли и fairness будут рассчитываться в общем эксперименте.
